# 技能调度器

你的任务是在合适的时机，把用户请求路由到仓库里已登记的某个 Skill，而不是自己猜测或凭训练记忆回答专业问题。

## 何时不路由

对简单事实问题、翻译、寒暄、通用改写等普通请求，直接回答，不要调用路由。

## 路由步骤

1. 遇到涉及 AI 产品拆解、加速学习、飞书（Lark）协作、深度研究、写作策划、金融交易、知识存储、多步工作流等专业场景的请求时，在本地运行只读命令：

   ```bash
   ~/.skill-library/bin/skillctl route "用户请求的关键意图"
   ```

   注意：只传关键意图摘要，不得保存用户请求原文到任何文件或状态里。

2. 输出格式为每行一个候选：`分数<TAB>英文ID<TAB>中文名称<TAB>简介`，最多三个候选。优先看用户是否已经直接说出某个 Skill 的精确中文名称或别名，若有则优先采用。

3. 判断候选是否明确：
   - 没有候选，或候选之间分数接近、意图不清 —— 没有把握时询问用户，用中文名称列出最多三个候选让用户选，不要自行猜测。
   - 唯一候选且明显匹配 —— 运行 `~/.skill-library/bin/skillctl route-status`；只有输出为"自动选择已启用"时才可以直接选用该候选，否则仍要用中文名称向用户确认。

4. 确认候选后，完整读取该 Skill 在仓库中的 `SKILL.md`（例如 `~/.skill-library/skills/<英文ID>/SKILL.md`），按其内容执行，不要只凭路由返回的一句话简介行事。

5. 涉及删除、覆盖、对外发送、真实系统变更等高风险或外部动作时，无论 Skill 内部怎么写，都要先向用户或独立获得确认，不能因为路由选中了某个 Skill 就自动执行破坏性操作。

## 边界

- 路由过程只读，不修改仓库、软链或配置。
- 不在一次任务里无理由叠加多个大型 Skill 的完整内容。
- 面板和路由结果只展示测试数据与当前状态，不包含真实对话内容。
